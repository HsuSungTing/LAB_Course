今天我希望利用 SystemVerilog 的 random 來對我的電路進行輸入測試。每次輸入都會等到對應的 output value 拉高後，才會進行下一筆輸入。為此，我設計了一個專門的 input task，它負責產生測試輸入並將其餵給電路。這個 task 會利用 System Value Log 的語法生成隨機測試，每次隨機決定一個行為，從五種可能的行為中選擇：Logging、Level Up、Battle、Skill、Inactive。

對於每個行為，輸入的方式都稍有不同，且所有訊號都是透過 interface 傳入電路。以 Logging 為例，task 會先將 action_valid 拉高一個時脈週期，將 action 送入 D，接著再拉高 date_valid 將日期送入 D，最後將 player_no_valid 拉高並送入玩家編號。整個過程每個訊號都依序拉高一個週期後拉低，以確保 DUT 可以正確讀取。

如果隨機選到的行為是 Level Up，則輸入流程如下：先將 action_valid 拉高一個週期，將 Action 設為 1 送入 D，接著拉高 type_valid 將 Training Type（0 到 3 的值）送入 D，再拉高 mode_valid 將 Mode（0 到 2 的值）送入 D，最後將 player_no_valid 拉高並送入玩家編號。

如果選到 Battle，流程則為：先將 sel_action_valid 拉高一個週期，將 Action 設為 2 送入 D，再拉高 player_no_valid 送入玩家編號，接著將 monster_valid 拉高三個週期，依序輸入三個 16-bit 的數字。

若選到 Use Skill，流程為：將 sel_action_valid 拉高一個週期，將 Action 設為 3 送入 D，接著在下一個週期拉高 player_no_valid 送入玩家編號，再拉高 mp_valid 並連續四個週期將四個數值輸入 D。

最後，如果行為是 Inactive，流程為：先將 sel_action_valid 拉高一個週期，將 Action 設為 4 送入 D，再拉高 date_valid 將日期送入 D，最後將 player_no_valid 拉高並送入玩家編號
